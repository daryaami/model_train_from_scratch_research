# Как снимать текст с химического датасета

Сравнение на шести русских страницах из `data/chem_dataset/chem_extracted`. Цель — текст, на котором можно учить LLM: связная проза и формулы, которые не разваливаются.

Выборка лежит в `ocr_research/sample/`, сырые ответы — в `ocr_research/results/`.

## Что сравнивалось

| Движок | Что это |
|---|---|
| Tesseract `rus+eng` | то, что уже стоит в `scripts/djvu_to_text.py` |
| RapidOCR PP-OCRv5 | отдельные модели `eslav` и `cyrillic`, детектор mobile и server |
| Docling | разбор страницы, таблицы и отдельная модель формул; текст снят тем же Tesseract |
| Marker 2 | разбор страницы моделью Surya через llama.cpp |
| MinerU pipeline | MinerU 3.4.5, бэкенд `pipeline`, языковая группа `east_slavic` |
| MinerU VLM | MinerU 4.0.12, уровень `standard`, модель MinerU2.5-Pro 1.2B через llama.cpp. Язык не задаётся |
| DeepSeek-OCR-2 | модель на 3.4B, промпт с разметкой страницы, веса `deepseek-ai/DeepSeek-OCR-2`, внимание eager на GPU |
| dots.ocr | модель на 3.0B, разбор страницы в JSON, веса `rednote-hilab/dots.ocr`. Зрение через SDPA, языковая модель eager |

Страницы: учебник Мингулиной (сплошной текст и уравнения), Крестов (таблицы термодинамики), Смит (ИК-спектроскопия), лабораторный практикум Фролова, скан фармакопеи без текстового слоя, журнальная статья про аллилирование (схема реакции, низкое разрешение).

Эталоном для прозы служил текстовый слой DjVu. У слоя свои дефекты: переносы продублированы (`сольвата-` / `сольватация`). Поэтому близость к слою не равна пригодности для обучения. Формулы сверялись со страницей.

## Проза

Доля слов длиннее 5 букв из текстового слоя, которые нашлись в ответе. Чем выше, тем лучше. Сканы без слоя в таблицу не входят.

| Страница | Tesseract | RapidOCR eslav | RapidOCR server | Docling | Marker | MinerU pipeline | MinerU VLM | DeepSeek-OCR-2 | dots.ocr |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| Общая химия | 0.92 | 0.79 | 0.83 | 0.92 | 0.90 | 0.89 | 0.92 | 0.88 | 0.92 |
| Термодинамика | 0.92 | 0.64 | 0.81 | 0.92 | 0.91 | 0.91 | 0.92 | 0.92 | 0.92 |
| ИК-спектроскопия | 0.94 | 0.81 | 0.85 | 0.94 | 0.94 | 0.93 | 0.94 | 0.93 | 0.94 |
| Коллоидная химия | 0.93 | 0.86 | 0.93 | 0.93 | 0.93 | 0.93 | 0.93 | 0.93 | 0.93 |

Marker на учебнике чуть ниже Tesseract по этой цифре, потому что склеивает переносы и выкидывает обрывки, которых полон текстовый слой. На ИК-спектроскопии и коллоидной химии цифры совпадают. Читать текст Marker легче: абзацы целые, заголовки на месте.

RapidOCR на этих книгах слабее Tesseract. Типичные поломки: пропадают пробелы (`Взаимодействиемежду`), кириллица путается с латиницей (`и` превращается в `H` или `B`), случайный регистр. Модель `eslav` и более широкая `cyrillic` почти не различаются. Более тяжёлый детектор server подтягивает RapidOCR, но до Tesseract не дотягивает. Двухколоночную фармакопею RapidOCR склеивает построчно, левый и правый столбец попадают в одну строку.

MinerU pipeline с группой `east_slavic` русский читает: доля длинных слов 0.89–0.93. В тексте остаются разорванные переносы (`сольвата- ция`) и склеенные слова (`Белыйкристаллическийпорошок`). Первый прогон MinerU 4 на уровне `basic` шёл китайской моделью PP-OCRv6: в этой сборке у локального pipeline нет выбора языка, и кириллица со страницы исчезла. Это была не проверка русского.

MinerU VLM язык не спрашивает. На этих четырёх страницах он держится рядом с Marker: 0.92–0.94, абзацы целые, переносы склеены.

DeepSeek-OCR-2 тоже склеивает переносы. На термодинамике, ИК и коллоидной химии доля длинных слов 0.92–0.93. На общей химии 0.88: текст связный, часть слов эталона в ответ не попала.

dots.ocr по прозе рядом с Marker и MinerU VLM: 0.92–0.94. Переносы он иногда оставляет (`расплывающе-ся`, `воз-духе`).

## Одни и те же места

Ниже короткие цитаты из ответов. Формулы записаны так, как их можно прочитать: индексы не развёрнуты в сырой LaTeX.

### Первая фраза учебника

На странице: «Взаимодействие между молекулами … (сольватация)».

| Движок | Как вышло |
|---|---|
| Tesseract | Взаимодействие между … (сольвата- ция) |
| RapidOCR | Взаимодействиемежду … H нонами … (сольвата- цня) |
| Docling | Взаимодействие между … (сольватация) |
| Marker | Взаимодействие между … (сольватация) |
| MinerU pipeline | Взаимодействие между … (сольвата- ция) |
| MinerU VLM | Взаимодействие между … (сольватация) |
| DeepSeek-OCR-2 | Взаимодействие между … (сольватация) |
| dots.ocr | Взаимодействие между … (сольватация) |

У текстового слоя DjVu перенос продублирован: там есть и `сольвата-`, и `сольватация`. Tesseract и pipeline повторяют этот разрыв. RapidOCR ещё склеивает слова и путает `и` с `H`.

### Уравнение уксусной кислоты

На странице: `CH3COOH + (n+m)H2O ⇌ CH3COO− · nH2O + H+ · mH2O`.

| Движок | Строка |
|---|---|
| Tesseract | `CH3COOH + (п-+ m)H,02 CH3COO7-nH,0 + Н*.тН.О` |
| RapidOCR | `CH3COOH + (n + m)H20=CH3COO-·nH20 + H+ mH20` |
| Docling | `CH3COH + (n+m)H2O ≠≠ CH3CO¯ · nH2O + …` |
| Marker | `CH3COOH + (n+m)H2O ⇌ CH3COO− · nH2O + H+ · mH2O` |
| MinerU pipeline | `CH3COOH + (n+m)H2O CH3COO− · nH2O + H+ · mH2O` |
| MinerU VLM | то же, что у Marker; номер уравнения `6` |
| DeepSeek-OCR-2 | то же, что у Marker; номер `(б)` |
| dots.ocr | то же, что у Marker; номер `(b)` |

Рядом на странице стоят `AB + (n+m)S ⇌ AB(n+m)S` и диссоциация на `A^{p+}` и `B^{q-}`. Marker, MinerU VLM, DeepSeek и dots.ocr снимают обе. У pipeline стрелка на этом месте пустая. Tesseract и RapidOCR заряды теряют. Docling теряет атом кислорода: `CH3COH` вместо `CH3COOH`.

### Фармакопея, три формулы в тексте

На странице: сульфид `Na2S·9H2O`, гипофосфит `NaH2PO2·H2O`, оксалат `(COONa)2`.

| Движок | Сульфид | Гипофосфит | Оксалат |
|---|---|---|---|
| Tesseract | `NaeS .ЭН2О` | `МаН.РО. . Н2О` | `(ЦООМа).` |
| RapidOCR | `№a2S·9H2O` | строка разъехалась по столбцам | `(ЦОО№а)2` |
| Docling | `Маз5 .ЭН2О` | `МанН.РО. . НэО` | `(ЦООМа).` |
| Marker | `Na2S·9H2O` | `NaH2PO2·H2O` | `(ЦООNa)2` |
| MinerU pipeline | `Na2S·9H2O` | `NaH2PO2·H2O`, с лишней точкой над O | `(ЦОО№а)2` |
| MinerU VLM | `Na₂S·9H₂O` | `NaH₂PO₂·H₂O` | `(ЦООNa)₂` |
| DeepSeek-OCR-2 | `Na₂S·9H₂O` | `NaH₂PO₂·H₂O` | `(ЦООНа)₂` |
| dots.ocr | `Na₂S·9H₂O` | `NaH₂PO₄·H₂O` | `(ЦООNa)₂` |

У DeepSeek в фосфорномолибдате пропал индекс: `Na3H4[P(Mo2O7)]·19H2O` вместо `…(Mo2O7)6·19H2O`. У dots.ocr индекс на месте, но буква P в скобках кириллическая. Marker, VLM и DeepSeek читают два столбца фармакопеи по очереди. RapidOCR мешает левый столбец с правым.

### Строка хлора в таблице II.18

Числа у тех, кто собрал таблицу, одни: `79,1 | 33,5 | −5,4 | −25,1 | −13,8 | 2,1 | 18,0`. На странице ион `Cl−`.

| Движок | Что стоит в строке |
|---|---|
| Tesseract | `Cl+ 79,1 33,5 —5,4 …`, числа вперемешку с соседними ионами |
| RapidOCR | `Cl+` и числа `Br−`, `I−` склеены в одну кашу |
| Docling | таблица есть, подписи ионов съехали относительно чисел |
| Marker | `Cl+` и верные числа; последняя ячейка `Rb+` равна 41,0 |
| MinerU pipeline | `Cl+` и верные числа, но столбцы соседних ионов съехали: числа `K+` попали к `Na+` |
| MinerU VLM | `Cl+` и верные числа; `Rb+` = 41,0 |
| DeepSeek-OCR-2 | `Cl+` и верные числа; последняя ячейка `Rb+` равна 14,0 |
| dots.ocr | `Cl+` и верные числа; `Rb+` = 41,0 |

Широкая таблица II.17 у Marker разрезана на две, шапка второй части поехала.

### Журнал, страница шириной 641 пиксель

На странице: «При аллилировании гваякола … эвгенол».

| Движок | Как вышло |
|---|---|
| Tesseract | аллилированпы гваякола … зегенол |
| RapidOCR | аллилнрованои гваякола … 3BГCH01 |
| Docling | аллилированпы гваякола … эвгенол |
| Marker | Аллилирование тваякола … кулороса … пилыю |
| MinerU pipeline | аллплированпи гваякола … звгснол |
| MinerU VLM | алаплированни гваякола … вред封锁 |
| DeepSeek-OCR-2 | аллиллярования … хлористым вляллом |
| dots.ocr | аллиллировании гваякола … эвгенол … вредолюк |

Схему с эвгенолом, хавибетолом и о-эвгенолом Marker и MinerU оставляют картинкой. DeepSeek и dots.ocr пытаются прочитать её как текст. Реакции в виде SMILES нет ни у кого. Апскейл при рендере новых деталей не добавляет. Mathpix умеет отдавать такие схемы как SMILES (`include_smiles`) и печатает кириллицу, но это облачный API. Ключей `app_id` и `app_key` на машине нет, поэтому Mathpix на выборке не запускался. Отдельный распознаватель структур (MolScribe, DECIMER, RxnScribe) тоже не гонялся.

## Скорость

На CPU, одна страница:

- Tesseract — около 2 секунд
- RapidOCR mobile — 2–7 секунд
- Docling — 3–7 секунд после загрузки моделей, первая страница около минуты
- Marker — 40–110 секунд на обычной странице, 3–3,5 минуты на таблице и на двухколоночной фармакопее
- MinerU pipeline — около 20–40 секунд на страницу после загрузки моделей
- MinerU VLM — 5–15 секунд на страницу после загрузки модели. Первая страница вместе со скачиванием весов заняла около минуты

На GPU, одна страница, после загрузки весов:

- DeepSeek-OCR-2 — 14–39 секунд на обычной странице, 62 секунды на таблице Крестова. Занял около 8 ГБ из свободных 10 ГБ. Внимание eager: в окружении нет flash-attn.
- dots.ocr — 24–50 секунд на обычной странице, 65 секунд на таблице, 87 секунд на общей химии. Первая попытка на полном разрешении просила 22 ГБ под матрицу внимания и не влезла. Повтор шёл с SDPA в зрительной части.

На GPU (RTX 3090, llama.cpp, свободно было около 10 ГБ) ИК-страница Marker заняла 18 секунд, коллоидная — 12. Остальные процессы на карте в этот момент не считали, но память держали, поэтому vLLM, который хочет почти всю карту, не запускался. VLM у MinerU 4 шёл на CPU: в поставке `mineru-llama-cpp` нет CUDA-библиотеки, хотя слоёв на видеокарту он просит 99.

Текущий `scripts/djvu_to_text.py` рендерит страницу без увеличения. Для низкого исходного разрешения это и есть потолок качества.

## Выбор

Для корпуса берём **Marker**.

Критерий — текст, который можно класть в обучение: связная русская проза и формулы без подмены состава. По этому критерию четыре сильных движка расходятся так.

| | Проза | Формулы и числа | Что попадёт в обучение лишнего |
|---|---|---|---|
| Marker | переносы склеены, абзацы целые | уксусная кислота, `Na2S·9H2O`, `NaH2PO2·H2O`, таблица II.18 с `Rb+` = 41,0 | широкая таблица II.17 разрезана, шапка второй части съехала; знак `Cl−` стал `Cl+`; номер уравнения `(b)`, не `(б)` |
| MinerU VLM | то же качество, доля длинных слов чуть выше | те же формулы, таблица II.18 на месте | в заголовке `§ V1.3` вместо `§ VI.3`; номер уравнения `6`; хвост таблицы II.17 без подписей строк; на плохом скане в текст попал китайский фрагмент |
| DeepSeek-OCR-2 | на общей химии 0.88, номер `(б)` кириллический | уксусная кислота верна, гипофосфит верен | последняя ячейка `Rb+` равна 14,0 вместо 41,0; в фосфорномолибдате пропал индекс 6; оксалат `(ЦООНа)2` |
| dots.ocr | 0.92–0.94, часть переносов разорвана | таблица II.18 с `Rb+` = 41,0 | гипофосфит записан как `NaH2PO4·H2O` |

`Cl+` вместо `Cl−` стоит у всех четырёх, этим знаком выбор не сделать. Схемы реакций не читает никто: Marker оставляет их картинкой, DeepSeek и dots.ocr дописывают бессвязный текст. Картинку из обучения проще выкинуть, чем вычищать выдуманные слова.

MinerU VLM — запасной вариант, если видеокарта занята: модель 1.2B, 5–15 секунд на страницу на CPU, химия на этой выборке та же. DeepSeek-OCR-2 и dots.ocr для полного прогона не берём: ошибка в индексе и в числе таблицы хуже, чем разрезанная широкая таблица.

## Вывод

Marker даёт связный русский текст, уравнение уксусной кислоты и таблицу II.18. На RTX 3090 страница занимает 12–18 секунд, если под llama.cpp есть около 10 ГБ. MinerU pipeline с `east_slavic` русский берёт и формулы по составу узнаёт, но для обучения текст хуже: переносы рваные, пробелы пропадают, стрелка равновесия выпадает, столбцы таблицы съезжают. Tesseract оставить как быстрый черновик: на чистой прозе он не хуже, формулы он портит. RapidOCR на этих русских книгах слабее Tesseract. Docling удобен как обёртка, но его модель формул и сборка таблиц слабее Marker.

Перед полным прогоном:

1. Рендерить DjVu достаточно крупно. Родной размер части сканов слишком мал.
2. Гнать Marker на GPU. На RTX 3090 страница занимает 12–18 секунд, если карте хватает свободной памяти под llama.cpp. Пока рядом лежат чужие процессы, vLLM лучше не поднимать: он пытается забрать почти всю память.
3. Страницы, где осталась только картинка, не считать распознанными: там схема реакции.
4. Иметь в виду редкие химические ошибки вроде знака заряда. На таблице Крестова `Cl−` стал `Cl+`.

Повтор прогона Marker на четырёх страницах с текстовым слоем: `bash ocr_research/run_marker.sh`. Скрипт смотрит на CUDA-сборку llama.cpp. Линейные движки: `ocr_research/.venv/bin/python ocr_research/run_bench.py line`. Docling: `ocr_research/.venv-docling/bin/python ocr_research/run_docling.py`.

MinerU VLM, язык не задаётся:

```bash
MINERU_MODEL_VLM_ENGINE=llama-cpp MINERU_MODEL_SMALL_BACKEND=onnx \
  ocr_research/.venv-mineru/bin/mineru-kit parse FILE -o OUT.md --tier standard --ocr-mode ocr
```

MinerU pipeline для русского:

```bash
ocr_research/.venv-mineru34/bin/mineru -p FILE -o OUT -b pipeline -l east_slavic -m ocr
```
